Privacy

This page says what Valet sends over the network, what it stores on your computer, what it does not have, and what happens to the data when you uninstall. It is a summary. The full text, with each statement tied to the code or test it comes from and with what was not checked, is in the repository: PRIVACY.md.

Short version. Valet makes two kinds of network request: a check for a new version of itself and, only if you have imported a Pro license, a license check. No file name, path, rule or file content is part of either. Everything else stays on your computer.

Buying a license happens outside the app and has its own data (the payment and your email), described below under "Buying a license". Buying is not open yet.

What goes over the network

The check for a new version

  • Valet makes an HTTPS GET to GitHub for a static JSON file. The address depends on the channel you choose in Settings, Updates: Stable or Beta.
  • The request has no body and no cookie. The installed version, the Windows version and the processor type are not sent. Versions are compared on your computer.
  • GitHub sees what any web server sees: your public IP address, the time and the connection data. What GitHub keeps is GitHub's.
  • When: 30 seconds after Valet starts, then once every 24 hours while Valet keeps running, and when you press "Check now". The automatic check runs only while "Check for updates automatically" (Settings, Updates) is checked.
  • An automatic check installs nothing. Installing needs a click and a confirmation.
  • You can switch the automatic check off in Settings, Updates, by unchecking "Check for updates automatically" (checked by default); "Check now" still works.
  • The Microsoft Store version makes no version check: updates come through the Store.

The license check

This part was checked against the code in the repository (license_client.rs, licensing.rs). No license server exists yet, so the check has never run against a real server, only against a local test one.

  • When: only if you have imported a Pro license. At activation, then at most once every 30 days (the app looks at startup and every hour, and a request goes out at most once every 24 hours, only when the last successful check is 30 days old or older), at "Check license now" and when you remove the license. The 14-day trial and the Free plan make no license request.
  • What is sent: exactly three fields: the license id (a random code from the license file), a machine identifier that is a one-way hash (the first 32 characters of the blake3 hash of a fixed text and the Windows MachineGuid), and the app version. The deactivate request has only the first two. The server also sees your IP address and the time, like any web server, and remembers which machines activated a license so that it can count activations (3 at most).
  • What is never sent: file names, paths, rules or counts of rules or files, the raw MachineGuid, the computer name, the Windows version, the email address in the license.
  • Where the license is: in the app data folder (the one with the database), as license.valet-license, plus activation.valet-token, the server's last answer. Files that are removed or replaced are moved to the subfolder license-removed; Valet does not delete them.
  • Removing the license in Settings sends a deactivate request, which frees that computer's activation, then moves the two files to license-removed. The request is best effort: without a connection the license is still removed from the computer, but the activation on the server stays taken until support frees it. Uninstalling does not do this.
  • Offline: Valet keeps the token; the license stays Pro for up to 60 days after the last successful check, then the app works as Free, losing nothing, until the next successful check.
  • When it is not active: in a build without a configured license server, the app makes no license request and a Pro license cannot be activated. The configuration files in the repository are empty (0 bytes), so the current builds make no license request.

Other connections

  • The installer downloads Microsoft WebView2 only if it is missing from the computer. That is the installer talking to Microsoft, not Valet.
  • WebView2 has its own update service; what it contacts is not covered here.
  • No network capture was made while Valet ran, so what Tauri and its plugins do beyond the above is read from code, not observed.

Buying a license

State. Buying is not open. What follows describes what is decided for when it opens (the contract in the repository, docs/LICENSING.md), not something that runs now. It has not been tried with a real merchant.

  • The merchant. The payment, VAT and refunds are handled by a merchant (Paddle or Stripe Managed Payments; not chosen yet). You pay on the merchant's page, opened in the browser; the app has no payment form. The merchant receives your payment details and your email address. What it keeps is under its own policy, which is not covered here.
  • The license server. It runs on Fly.io. The region is not chosen yet. It receives a signed notification (webhook) from the merchant for a purchase and for a refund, and it keeps: the license id, the merchant's order ids, the one-way hashed ids of the computers that activated the license, and the dates of those activations. It does not keep your email address.
  • Your email. The server receives it from the merchant at the moment of purchase (with Paddle it reads it through Paddle's API) and uses it once: it puts it in the license file and sends the message with the license through Resend, an email delivery service. Resend processes the address to deliver the message; what it keeps is under its own policy. After that the email is only in the message and in your license file, on your computer.
  • Refunds. Within 14 days of purchase, through the merchant. The merchant tells the server, and the server marks the license as revoked. The app learns about it at the next license check.
  • IP addresses. The server limits requests per IP address in the memory of the process and does not write them to a log or keep them. The hosting (Fly.io) sees what any hosting sees.
  • What does not change. The app still does not send your email, file names, paths or contents. The app's requests are the ones described above.

The statements about what the server keeps come from the contract in the repository. The server with the merchant part does not run yet, so they have not been checked on a running server.

What Valet stores on your computer

  • In %APPDATA%\ro.valetapp.desktop: the database with the rules and the operation journal (the full source and destination path of every operation, sizes, content hashes of the files moved, the state of each operation) and the date the trial started, the watched folders, settings, approvals and, if you imported a license, its files. In the Microsoft Store version Windows keeps them in a folder of the package, and uninstalling the Store app deletes it. The journal is never trimmed for plan reasons.
  • In %LOCALAPPDATA%\ro.valetapp.desktop\logs: the file valet.log, at most 5 files of 2 MB. The normal log lines of Valet carry no file paths (read from the code, not tested; some operating system error texts were not checked). "Detailed log (for troubleshooting)" in Settings, off by default, can write paths. Valet never sends the logs anywhere; if you send one to someone for support, read it first.
  • Start with Windows, if you turn it on, writes a value under HKCU\Software\Microsoft\Windows\CurrentVersion\Run.

What Valet does not have

  • No telemetry: nothing counts what you do, and there is no analytics library in the program.
  • No crash reports. A crash leaves a line in the local log and nothing else. If crash reports are added later, they will be opt-in and will show exactly what is sent.
  • No account, no advertising, no cloud copy of your rules, journal or files.

Nothing prevents a future version from adding a network call, and no test fails when one is added; if that happens, this page and the full document change.

Uninstalling

  • Your data is kept by default. The uninstaller has a checkbox "Delete the application data", unticked at the start; ticked, it removes the two folders above (so History, undo and the license files are gone).
  • Uninstalling undoes nothing: moved files stay where they are, and files in the Recycle Bin stay in the Bin.
  • The uninstaller does not contact the license server. To free the activation, remove the license in Settings first.
  • The Microsoft Store version has no "Delete the application data" checkbox: uninstalling the app deletes its data, including History and undo.

This site

The site is static HTML and one CSS file. It has no scripts, cookies, analytics, forms, or fonts and images from other sites. Hosting has not been chosen yet; like any host, it will see the ordinary data of a web server.
